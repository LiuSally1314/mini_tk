# 自动化流程执行框架 — 程序文档

## 一、项目概述

本项目是一个基于 **Airtest + RapidOCR** 的 Android 自动化流程执行框架。核心思想是：

- **配置驱动**：所有业务流程写在 YAML 文件中，无需改代码即可新增/修改流程。
- **动作原子化**：把点击、查找、循环、条件判断等拆成通用动作（action），流程由这些动作组合而成。
- **OCR 定位**：通过截屏 + RapidOCR 识别页面文本，支持精确/模糊匹配、区域限定。
- **异步终止**：支持在循环中异步监听"终止关键词"（如"最高等级"），命中后跳出循环或跳到下一个坐标项。
- **方法扩展**：通过 `run_method` 可以在流程中调用 Python 方法，实现复杂业务逻辑（如技能扫描、计划文件读写）。

## 三、快速开始

### 1. 配置设备

编辑 `config/config.yaml`：

```yaml
device:
  uri: "Android:///192.168.31.102:37781"
```

### 2. 选择流程

```yaml
active_flow: "将领技能升级"
```

### 3. 运行

```bash
python main.py
```

程序会加载主配置、连接设备、读取 `config/flows/` 下所有流程、执行 `active_flow` 指定的流程。

## 四、主配置说明（config.yaml）

| 字段 | 说明 |
|------|------|
| `device.uri` | 设备连接地址，格式 `Android:///<adb地址>` |
| `output.json_filename` | OCR 结果 JSON 文件名 |
| `output.query_json_filename` | 查询结果 JSON 文件名 |

| `defaults.retry` | OCR 查找失败重试次数 |
| `defaults.retry_interval` | 重试间隔（秒） |
| `defaults.interval` | 通用动作间隔（秒） |
| `defaults.exact` | 是否精确匹配文本 |
| `defaults.sleep` | 每步执行后休眠（秒） |
| `defaults.enabled` | 步骤是否启用 |
| `active_flow` | 当前激活流程名（对应 `flows/<name>.yaml`） |
| `flows_dir` | 流程目录 |

## 五、流程 YAML 结构

```yaml
loop_count: 1          # 整个流程循环次数

steps:                 # 步骤列表
  - action: click
    remark: "日志说明"
    text: "文本说明"
    target: coords
    coords: [553, 2257]
    times: 1
    sleep: 0.5
```

### 通用字段

| 字段 | 说明 |
|------|------|
| `action` | 动作名（必填） |
| `remark` | 日志说明 |
| `text` | 目标文本（用于查找类动作） |
| `expect_text` | 期望出现的页面关键词（字符串/列表/规则字典） |
| `coords` | 坐标 `[x, y]` |
| `coords_list` | 坐标列表 `[[x,y], ...]` |
| `times` | 次数 |
| `interval` | 通用间隔（秒） |
| `retry` | OCR 重试次数 |
| `retry_interval` | 重试间隔（秒） |
| `exact` | 是否精确匹配 |
| `sleep` | 步骤后休眠（秒） |
| `optional` | 找不到时是否跳过 |
| `enabled` | 是否启用 |
| `before` / `after` | 前置/后置子步骤 |

## 六、动作（Action）参考

### 1. `click` — 点击

```yaml
- action: click
  remark: "点击确定"
  target: coords        # coords | last | skill
  coords: [553, 2257]
  times: 1
  interval: 0.2
  sleep: 0.5
```

- `target: coords` → 使用本步 `coords`
- `target: last` → 使用上一次 `find` 记录的坐标
- `target: skill` → 同 `last`

### 2. `find` — OCR 查找（记录坐标）

```yaml
- action: find
  text: "确定"
  exact: false
  region: [400, 1500, 700, 1900]
  expect_text: "升级页面"
```

支持 `region`（绝对区域）或 `coords + region_size/region_w/region_h`（以坐标为中心的矩形）。

### 3. `find_click` — 查找并点击

```yaml
- action: find_click
  text: "升级"
  expect_text:
    mode: or
    keywords: ["建造", "研究", "升级"]
  times: 2
  interval: 0.5
```

### 4. `wait` — 纯等待

```yaml
- action: wait
  seconds: 1.0
```

### 5. `wait_text` — 等待文本出现

```yaml
- action: wait_text
  text: "确定"
  retry: 5
  retry_interval: 1.0
  optional: true
```

### 6. `dump_ocr` — 打印当前页面 OCR（调试）

```yaml
- action: dump_ocr
```

### 7. `repeat` — 次数循环

```yaml
- action: repeat
  times: 7
  steps:
    - action: click
      target: coords
      coords: [849, 2282]
    - action: click
      target: coords
      coords: [500, 1682]
```

### 8. `for_each_coord` — 遍历坐标列表

```yaml
- action: for_each_coord
  coords_list:
    - [294, 895]
    - [540, 895]
  click_wait: 0.5
  times: 10           # 每个坐标项内部循环次数
  interval: 0.3
  close_popup_before_next: false
  global_abort:
    keywords: ["最高等级"]
  steps:
    - action: click
      target: coords
      coords: [356, 2288]
```

### 9. `poll_click` — 轮询点击直到页面关闭

```yaml
- action: poll_click
  coords_list:
    - [389, 1328]
    - [895, 1313]
  expect_text: "升级"
  click_text: "升级"
  times: 20
  interval: 1.0
```

### 10. `abort_check` — 终止检查

**同步**：

```yaml
- action: abort_check
  abort_text:
    mode: mixed
    rules:
      - type: must
        keywords: ["最高等级"]
  on_match: break_outer
  on_miss: next
  retry: 1
  retry_interval: 0.3
```

**异步**：

```yaml
- action: abort_check
  async: true
  abort_text:
    mode: mixed
    match_mode: any
    rules:
      - type: must
        keywords: ["最高等级"]
      - type: not
        keywords: ["确定"]
  on_match: break_outer
  consume_at: outer_end
  retry_interval: 0.3
```

**走向值**：

| 值 | 含义 |
|----|------|
| `break_outer` | 抛出 `SkillAbort`，跳到最外层 `for_each_coord` 的下一个坐标 |
| `break_inner` | 抛出 `LoopBreak`，跳出最近一层 `repeat` / `for_each_coord` |
| `next` | 继续下一步 |

**消费时机 `consume_at`**：

| 值 | 含义 |
|----|------|
| `step` | 立即消费命中 |
| `loop_end` | 等到最近一层循环结束时消费 |
| `outer_end` | 等到外层 `for_each_coord` 当前项结束时消费 |

### 11. `call_flow` — 调用子流程

```yaml
- action: call_flow
  flow: 将领技能强化
  before:
    - action: click
      target: coords
      coords: [278, 355]
  after:
    - action: wait
      seconds: 1.0
```

### 12. `run_method` — 调用 Python 方法

```yaml
- action: run_method
  method: scan_general_skills
  store: data
  params:
    anchor_coords:
      - [226, 1344]
      - [743, 1344]
    pattern: "[Ll][Vv]\\.?\\s*(\\d+)\\s*/\\s*(\\d+)"
    file: "data/general_plan.json"
```

内置方法：

| 方法 | 作用 |
|------|------|
| `scan_general_skills` | 扫描将领技能等级，写入计划文件 |
| `get_click_target` | 读计划文件，判断并点击下一个技能坐标；全部完成时抛 `LoopBreak` |
| `update_click_count` | 更新已点次数 |

## 七、关键词匹配规则

`expect_text` / `abort_text` 支持三种写法：

### 1. 字符串

```yaml
expect_text: "建造"
```

子串匹配。

### 2. 字符串列表（OR）

```yaml
expect_text: ["建造", "研究", "升级"]
```

任一命中即可。

### 3. 规则字典

```yaml
expect_text:
  mode: mixed          # and | or | mixed
  match_mode: all      # all | any（仅 mixed 有效）
  rules:
    - type: must       # must(全部出现) | any(任一出现) | not(全部不出现)
      keywords: ["建造"]
    - type: not
      keywords: ["取消"]
```

## 八、核心模块说明

### `config/loader.py`

- `load_config(path)`：加载主配置，合并默认值，扫描 `flows_dir` 下所有 YAML 流程。
- 返回的 config 中 `flows` 字段为 `{流程名: 流程数据}`。

### `core/device.py` — `DeviceManager`

| 方法 | 说明 |
|------|------|
| `connect(uri)` | 连接设备 |
| `is_connected()` | 是否已连接 |
| `disconnect()` | 断开连接 |
| `touch(coords, duration)` | 点击 |
| `double_click(coords)` | 双击 |
| `swipe(start, end, duration)` | 滑动 |
| `input_text(text, enter)` | 输入文本 |
| `adb_shell(command)` | 执行 ADB 命令 |
| `adb_pull / adb_push` | 拉取/推送文件 |
| `snapshot(filename)` | 截屏 |

### `core/ocr_finder.py` — `OcrFinder`

| 方法 | 说明 |
|------|------|
| `find_text(dm, target, exact, region)` | 查找单个文本，返回中心坐标 |
| `find_texts(dm, targets, exact, region)` | 一次截图查多个目标，返回 `{alias: coord}` |
| `find_page_text(dm, region)` | 返回整页 OCR 文本（`\n` 分隔） |
| `get_page_ocr_data(dm)` | 返回原始 OCR 结果 `[[box, text, score], ...]` |
| `make_region(center, half_w, half_h)` | 构造区域元组 |

### `core/keyword_matcher.py`

- `check_keywords_match(text, config)`：核心匹配函数，支持字符串/列表/规则字典。
- `only_not_rules_matched(text, config)`：判断是否仅 `not` 规则命中（用于连续确认计数）。
- `set_text_clean_enabled(bool)`：是否开启去空白匹配。

### `core/abort_checker.py` — `AbortChecker`

- 同步检查：`check_sync(step)`
- 异步监听：`_start_async(step)` / `stop_async()` / `check_async_hit(phase)`
- 异常：`SkillAbort`（外层中止）、`LoopBreak`（内层中止）
- 相同配置复用监听线程，避免重复启动导致计数重置。

### `core/actions.py` — `ActionRunner`

核心执行器，负责：

- 动作分发（`run_step`）
- `before` / `after` 子步骤执行
- 全局终止监听（`set_global_abort`）
- 异步 abort 命中检查（`_check_async_abort_hit`）
- 内置业务方法（`scan_general_skills` / `get_click_target` / `update_click_count`）
- 子流程调用（`do_call_flow`），带循环引用检测

### `core/flow_runner.py` — `FlowRunner`

- 读取 `active_flow`，按 `loop_count` 循环执行 `steps`。
- 每一步调用 `ActionRunner.run_step`，失败则跳过本循环剩余步骤。

### `core/poll_clicker.py` — `PollClicker`

- 轮询点击同一坐标（或坐标列表），直到页面出现/消失指定文本。
- 支持 `coords_list` 显式指定坐标，或通过 `start_text` / `end_text` 自动推算 2×2 区域。
- 返回统计：`processed` / `finished` / `clicks` / `errors`。

## 十、执行流程时序

```
main.py
  └─ load_config("config/config.yaml")
       ├─ 读主配置，深合并默认值
       └─ 扫描 config/flows/*.yaml → config["flows"]
  └─ DeviceManager.connect(uri)
  └─ FlowRunner(dm, config).run()
       └─ 取 active_flow 对应流程
       └─ for n in range(loop_count):
            for step in steps:
              ActionRunner.run_step(step)
                ├─ 检查 enabled
                ├─ 检查异步 abort 命中
                ├─ 执行 before 子步骤
                ├─ 分发到具体 handler
                └─ 执行 after 子步骤
```

## 十一、扩展指南

### 新增一个动作

1. 在 `ActionRunner` 中实现 `do_xxx(self, step) -> bool`。
2. 在 `run_step` 的 `handler` 字典中注册 `"xxx": self.do_xxx`。
3. 在流程 YAML 中使用 `action: xxx`。

### 新增一个业务方法

1. 在 `ActionRunner` 中实现方法，签名与 `params` 对应。
2. 流程中使用：

```yaml
- action: run_method
  method: 你的方法名
  store: 结果键
  params:
    key: value
```

### 新增一个流程

1. 在 `config/flows/` 下新建 `<流程名>.yaml`。
2. 编写 `loop_count` 与 `steps`。
3. 在主配置中把 `active_flow` 改为该流程名，或通过 `call_flow` 被其他流程调用。

## 十二、异常与控制流

| 异常 | 抛出者 | 捕获者 | 效果 |
|------|--------|--------|------|
| `SkillAbort` | `abort_check` / 全局终止 | `for_each_coord` | 跳到下一个坐标项 |
| `LoopBreak` | `abort_check` / `get_click_target` | `repeat` / `for_each_coord` | 跳出当前循环 |
| `UserExit` | 用户操作 | `main.py` | 退出程序 |

## 十三、调试技巧

1. **`dump_ocr`**：打印当前页面所有 OCR 文本及坐标，用于确认识别效果。
2. **`debug: true`**：`scan_general_skills` 会打印每个 LV 匹配项和将领识别结果。
3. **`optional: true`**：让找不到文本的步骤不报错，继续执行。
4. **`enabled: false`**：临时禁用某一步。
5. **截图目录**：`截屏/` 下保留每次 OCR 的截图（默认执行后删除，可改 `ocr_finder.py` 保留）。
6. **数据文件**：`data/general_plan.json` 记录技能计划，可手动查看/修改。

## 十五、注意事项

1. **坐标硬编码**：所有 `coords` 基于特定分辨率，换设备需重新标定。
2. **异步 abort 线程**：`for_each_coord` 每个坐标项开始前会 `stop_async`，结束时也会 `stop_async`，避免线程泄漏。
3. **循环引用**：`call_flow` 通过 `_include_stack` 检测循环引用，避免无限递归。
4. **`run_method` 异常**：`LoopBreak` / `SkillAbort` 会向上抛，其他异常会被捕获并返回 `False`。
5. **`expect_text` 兼容**：同时兼容旧字段 `page_keyword` / `confirm_keyword`。
