# 项目简介文档

## 一、项目概述

本项目是一个基于 **Android + Airtest + RapidOCR** 的自动化操作框架，用于在安卓设备上执行游戏或 App 的自动化任务。核心思想是：

- **通用能力下沉到 core**：OCR 解析、文本匹配、设备操作、动作执行、流程调度等与业务无关的能力统一封装。
- **业务逻辑上浮到 flows**：具体某个游戏/场景的字段解析（建筑、邮件、坦克、将领技能……）写在 `core/flows/<name>.py` 中，通过注册机制自动挂载。
- **配置驱动执行**：流程步骤全部写在 `config/flows/*.yaml` 中，通过 `action` 字段选择动作，无需改代码即可调整执行逻辑。

整体分层结构：

```
main.py                    ← 程序入口
config/
  ├─ config.yaml           ← 主配置（设备、默认值、激活流程）
  ├─ loader.py             ← 配置加载器
  └─ flows/*.yaml          ← 各业务流程步骤定义
core/
  ├─ device.py             ← 设备连接与基本操作（点击/滑动/输入/ADB/截图）
  ├─ ocr_finder.py         ← 截图 + RapidOCR，查找文本坐标
  ├─ ocr_parser.py         ← OCR 结果通用清洗与结构化
  ├─ keyword_matcher.py    ← 关键词规则匹配（字符串/列表/字典 mixed）
  ├─ abort_checker.py      ← 终止检查（同步/异步 + 走向控制）
  ├─ actions.py            ← 动作执行器（ActionRunner）
  ├─ flow_runner.py        ← 流程调度器（循环、时间限制、统计）
  └─ flows/                ← 业务方法注册中心
       ├─ __init__.py      ← 自动扫描并注册所有 FlowMethods 子类
       ├─ base.py          ← FlowMethods 基类，注入上下文
       ├─ building.py      ← 建筑升级信息保存
       └─ email_get.py     ← 邮箱信息保存
```

---

## 二、运行流程

1. `main.py` 调用 `load_config()` 加载主配置与所有流程 YAML。
2. 启动时清空坐标缓存 `data/coord_cache.json`。
3. 通过 `DeviceManager.connect()` 连接 Android 设备（Airtest `connect_device`）。
4. `FlowRunner` 读取 `active_flow` 对应的 YAML 流程，按 `loop_count` 循环执行 `steps`。
5. 每个 step 交给 `ActionRunner.run_step()`，根据 `action` 字段分发到具体 handler。
6. 支持 `end_time` 时间限制，到点强制退出并打印统计。

## 三、核心模块说明

### 1. `device.py` — 设备管理

封装 Airtest 常用操作：

| 方法 | 说明 |
|---|---|
| `connect(uri)` | 连接设备，如 `Android:///192.168.31.33:39869` |
| `touch / double_click / swipe` | 点击、双击、滑动 |
| `input_text(text, enter)` | 输入文本 |
| `adb_shell / adb_pull / adb_push` | ADB 命令、文件拉取/推送 |
| `snapshot(filename)` | 截屏，返回图片路径 |

所有方法内部都做了连接状态检查与异常捕获，失败返回 `False` 或 `None`。

---

### 2. `ocr_finder.py` — OCR 查找

- 使用 `RapidOCR` 引擎。
- 截图文件命名带时间戳 + 毫秒 + 线程 ID，避免并发冲突，识别后自动删除。
- 输出结果统一按「从上到下、从左到右」排序（`sort_boxes_top_to_bottom_left_to_right`）。
- 提供接口：
  - `find_text(target, exact, region, index)` → 返回单点坐标
  - `find_texts(targets, exact, region, indexes)` → 返回多个目标的坐标字典
  - `find_page_text(region)` → 返回整页文本（按行拼接）
  - `get_page_ocr_data()` → 返回原始 `[[box, text, score], ...]`

---

### 3. `ocr_parser.py` — 通用 OCR 清洗与结构化

与业务完全解耦，提供：

- **文本清洗**：`clean_text()`（去空白 / NFKC 归一化 / 可选去标点）
- **坐标工具**：`box_to_bounds()`、`box_to_center()`
- **主入口**：`parse_page_data()` 兼容两种原始格式，输出 `OcrItem` 列表
- **过滤**：`filter_by_region` / `filter_by_range` / `filter_by_predicate`
- **查找**：`find_by_text` / `find_nearest`
- **分组**：`group_by_row`（固定行高）/ `merge_lines`（按 y 容差聚类）
- **拼文本**：`lines_to_text()`

`OcrItem` 字段：`text / raw_text / cx / cy / x1 / y1 / x2 / y2 / score / extra`。

---

### 4. `keyword_matcher.py` — 关键词匹配

支持三种配置形式：

```yaml
# 1. 字符串 → 子串匹配
text: "建造"

# 2. 列表 → 任一命中
text: ["免费加速", "加速"]

# 3. 字典规则
abort_text:
  mode: mixed            # and / or / mixed
  match_mode: any        # all（默认）/ any
  rules:
    - type: must         # 全部关键词都出现
      keywords: ["最高等级"]
    - type: any          # 任一关键词出现
      keywords: ["确定", "领取"]
    - type: not          # 全部关键词都不出现
      keywords: ["错误"]
```

辅助函数 `only_not_rules_matched()` 用于判断是否仅 `not` 规则触发（配合 `not_confirm_count` 连续确认）。

---

### 5. `abort_checker.py` — 终止检查

用于在流程中监听终止条件，支持同步与异步两种模式。

**走向值（on_match / on_miss）：**

| 值 | 行为 |
|---|---|
| `break_outer` | 抛出 `SkillAbort`，跳到最外层 `for_each_coord` 的下一个坐标 |
| `break_inner` | 抛出 `LoopBreak`，跳出最近一层 `repeat / for_each_coord` 内循环 |
| `next` | 继续下一步 |

**消费时机（consume_at）：**

| 值 | 说明 |
|---|---|
| `step` | 立即消费命中 |
| `loop_end` | 等到最近一层循环结束时消费 |
| `outer_end` | 等到外层 `for_each_coord` 当前项结束时消费 |

**同配置复用**：异步线程通过 signature 比较，若配置未变则复用现有线程，避免 `repeat` 每轮重启导致 `not_confirm_count` 被重置。

---

### 6. `actions.py` — 动作执行器（ActionRunner）

执行单个 step，支持的动作：

| action | 说明 |
|---|---|
| `find` | 查找文本（可配合 `expect_text` 做页面确认） |
| `click` | 点击（`target: last / coords`，支持 `offset_x / offset_y`、`times`、`interval`） |
| `find_click` | 查找并点击（支持 `name` 坐标缓存 + `cache_ttl`） |
| `wait` | 等待指定秒数（分片检查异步终止） |
| `wait_text` | 等待文本出现（带重试） |
| `abort_check` | 调用 AbortChecker |
| `dump_ocr` | 打印当前页面 OCR 内容 |
| `repeat` | 固定次数循环子步骤 |
| `for_each_coord` | 遍历坐标列表，每个坐标内循环执行子步骤 |
| `poll_click` | 轮询点击（调用 `PollClicker`） |
| `call_flow` | 调用子流程（支持 `before / after` 前后置动作） |
| `run_method` | 调用 flows 中注册的业务方法 |

**坐标缓存**：`find_click` 配了 `name` 时会把坐标写入 `data/coord_cache.json`，下次优先读缓存，`cache_ttl` 控制过期时间。

**全局终止**：`for_each_coord` 支持 `global_abort.keywords`，每步前检查命中即抛出 `SkillAbort`。

**内建方法**（`scan_general_skills / get_click_target / update_click_count`）用于将领技能升级的扫描-点击-计数闭环。

---

### 7. `flow_runner.py` — 流程调度器

- 读取 `active_flow` 对应 YAML，按 `loop_count` 循环执行。
- 支持 `end_time`（绝对时间 `YYYY-MM-DD HH:MM:SS` 或当天时刻 `HH:MM:SS`）。
- 每个循环、每个步骤前都检查时间限制，超时抛 `TimeLimitReached`。
- 结束后打印：总耗时、计划/实际循环数、成功/中断轮次、单轮平均/最快/最慢。

---

### 8. `core/flows/` — 业务方法注册中心

- `base.py` 定义 `FlowMethods` 基类，通过 `bind(runner)` 注入上下文，子类可透明访问 `self.dm / self.finder / self.defaults / self.last_coord / self._action_data`。
- `__init__.py` 自动扫描包内所有 `.py`，实例化 `FlowMethods` 子类，收集所有 public 方法进全局 registry。
- `ActionRunner.run_method` 通过 registry 查找并调用，参数由 YAML `params` 传入，返回值可存到 `_action_data[store]`。
- 与内建动作同名的会被拒绝注册（`BUILTIN_METHODS`）。

现有业务方法：

| 方法 | 所属类 | 功能 |
|---|---|---|
| `save_upgrade_building_info` | `BuildingFlow` | 识别建筑标题、升级时间、资源表，按「建筑+等级」去重追加 JSON |
| `save_upgrade_building_time_info` | `BuildingFlow` | 识别「花费 xxx 个金币」，更新或插入对应记录 |
| `save_email_info` | `EmailGetFlow` | 解析邮件详情页，提取数量/名称/描述，按 id 去重写入 CSV |

---

### 9. `poll_clicker.py` — 轮询点击器

用于「反复点同一坐标，直到页面出现/消失指定文本」的场景：

- 支持 `coords_list` 直接指定坐标列表；
- 或通过 `start_text / end_text` 自动推算 2×2 区域四个中心点；
- 每个坐标反复点击，直到 `expect_text` 消失或达到 `max_times`；
- 输出统计：处理坐标数、完成数、成功点击数、错误数。

## 四、配置说明

### 主配置 `config/config.yaml`

```yaml
device:
  uri: "Android:///192.168.31.33:39869"

output:
  json_filename: "ocr_result.json"
  query_json_filename: "query_result.json"
  base_dir: "截屏"

defaults:
  retry: 3              # OCR 查找失败重试次数
  retry_interval: 1.0   # 重试间隔（秒）
  interval: 0.5         # 通用动作间隔
  exact: true           # 文本精确匹配
  sleep: 0.1            # 每步执行后休眠
  enabled: true
  cache_ttl: 300        # 坐标缓存过期（秒）

active_flow: "邮箱领取"  # 当前激活流程
flows_dir: "config/flows"
```

### 流程配置 `config/flows/*.yaml`

每个流程文件包含：

```yaml
loop_count: 1000000          # 循环次数
end_time: "2026-09-30 06:30:00"  # 可选，到点强制停止

steps:
  - action: click
    remark: "买5次"
    target: coords
    coords: [832, 2091]
    times: 1
    sleep: 0.5
```

步骤通用字段：`enabled / remark / text / name / before / after`。

## 五、典型使用示例

### 1. 固定坐标点击流程（如「训练有素」）

```yaml
loop_count: 1000000
end_time: "2026-09-30 06:30:00"
steps:
  - action: click
    target: coords
    coords: [832, 2091]
    times: 1
    sleep: 0.5
```

### 2. 查找并点击（带坐标缓存）

```yaml
- action: find_click
  name: "点击第一个邮件"
  text: "GM邮件"
  index: 0
  cache_ttl: 6000
  times: 1
  sleep: 3
```

### 3. 遍历坐标 + 异步终止监听（如「将领技能精工」）

```yaml
- action: for_each_coord
  coords_list: [[294, 895], [540, 895], ...]
  steps:
    - action: abort_check
      abort_text:
        mode: mixed
        rules:
          - type: must
            keywords: ["最高等级"]
      on_match: break_outer
      on_miss: next

    - action: repeat
      times: 7
      steps:
        - action: click
          target: coords
          coords: [849, 2282]
        - action: abort_check
          async: true
          abort_text: { mode: mixed, match_mode: any, rules: [...] }
          on_match: break_outer
          consume_at: outer_end
        - action: click
          target: coords
          coords: [500, 1682]
```

### 4. 调用业务方法（如「建筑升级」）

```yaml
- action: run_method
  method: save_upgrade_building_info
  params:
    file: data/upgrade_building_info.json
  enabled: true
```

### 5. 组合流程（如「将领技能精工强化」）

```yaml
- action: call_flow
  flow: 将领技能强化
  before:
    - action: click
      target: coords
      coords: [278, 355]
  after:
    - action: wait
      seconds: 1.0
```

## 六、扩展方式

### 新增业务方法

1. 在 `core/flows/` 下新建 `<name>.py`；
2. 定义 `class XxxFlow(FlowMethods): ...`；
3. 在类中写 public 方法（不以 `_` 开头）；
4. 重启程序，注册中心自动扫描并挂载，YAML 里用 `run_method` 调用。

无需修改任何其他文件。

### 新增流程

在 `config/flows/` 下新建 `<name>.yaml`，主配置 `active_flow` 改为对应文件名即可。

## 七、关键设计要点

1. **业务与框架解耦**：`core/ocr_parser.py` 只做清洗/结构化，业务解析在各 `flows/<name>.py` 中完成。
2. **配置驱动**：动作、参数、坐标、关键词全部写在 YAML，改流程不改代码。
3. **异步终止监听**：`abort_check` 支持后台线程持续 OCR，命中后按 `on_match` 抛出异常，配合 `consume_at` 精确控制消费时机。
4. **同配置复用线程**：避免 `repeat` 内每轮重启异步线程导致 `not_confirm_count` 计数被重置。
5. **坐标缓存**：`find_click` 带 `name` 时缓存坐标，`cache_ttl` 控制过期，减少重复 OCR。
6. **时间限制**：`end_time` 支持绝对时间与当天时刻，到点强制退出并打印统计。
7. **异常分流**：`SkillAbort`（外层中止）与 `LoopBreak`（内层中止）分离，`for_each_coord` 捕获 `SkillAbort` 跳到下一个坐标，`repeat` 捕获 `LoopBreak` 跳出当前循环。
